## Фаза 1 — Минимальный сквозной путь: клиент видит сервер

Раньше доказательства масштаба (следующая фаза) — самый тонкий срез через весь стек разом, почти не требующий уже спроектированной тяжёлой архитектуры (ECS, двухфазный тик, ярусы репликации). Не пересекается с фазой 2 — можно делать в любом порядке относительно неё или параллельно, это два разных вопроса (жива ли связь целиком vs держит ли сервер масштаб). Подробная спецификация — раздел 20 основного документа.

- [ ] Клиент запускается сразу в игру, без меню — окно (winit) + инициализация Vulkan-бэкенда (первого по порядку, раздел 2.1 рендер-документа) + подключение по сети сразу при старте, адрес сервера — из конфига/аргумента запуска, не окончательное решение по финальному UX (раздел 20.4)
- [ ] Рукопожатие: проверка версии протокола до разбора любых данных (раздел 20.2)
- [ ] Полный снимок состояния при входе, отдельно от дельт — новому клиенту нечего дельтить (раздел 20.3)
- [ ] Сервер отвечает хоть чем-то реальным — минимум текущее состояние погоды (раздел 11), реально полученное с сервера, не захардкоженное на клиенте
- [ ] Свободная камера — WASD + мышь, отдельно от ECS, постов и кораблей, ни к чему не привязана
- [ ] Рендер океана по волновому спектру (раздел 12.3) на реально полученном от сервера значении силы непогоды
- [ ] Минимальный отладочный оверлей — fps и статус подключения ("подключаюсь"/"потеряно"), не полноценный HUD (раздел 20.4)
- [ ] Таймаут и обработка разрыва связи без краша клиента (раздел 20.5)
- [ ] Логирование подключений/отключений/ошибок протокола через `tracing` сразу, не постфактум (раздел 20.6)

## Фаза 6 — Сеть

- [ ] Слои репликации и интерес (раздел 3) — числа частот НЕ трогать до результатов стресс-теста
- [ ] Сериализация — postcard (раздел 3.5)
- [ ] Голосовая связь: три канала (локальный по SpatialGrid, корабельный, флотский командный), релей через сервер, Opus, ненадёжная доставка (раздел 17)
- [ ] Вход на сервер как в Squad: после загрузки — меню выбора стороны; блокировка по балансу (переключатель в конфиге владельца: войти можно только за сторону, где людей меньше); потолок команды до 100 на сторону; смена стороны по клавише (по умолчанию CAPS LOCK); после вылета место резервируется на 1 минуту, пост освобождается сразу; при входе и смене стороны выбираются фракция и страна, смена — с обязательной паузой (что такое фракция и страна — открыто). Решает сервер в момент запроса, не меню клиента; нужно отдельное состояние игрока «подключён, сторону не выбрал» (раздел 20.7). В первом сквозном пути (фаза 1) этого шага нет
- [ ] Конфиг сервера — файл настроек владельца, пока: блокировка выбора стороны и потолок команды (раздел 23, `server/config`); редактируется из панели управления (раздел 6.4)
- [ ] Список серверов — через Steam (решено как направление, раздел 6.3): автоподбора игроков в бой нет, игрок выбирает сервер из списка. Серверная сторона Steamworks проверена по документации (вход сервера в Steam, название/карта/игроки/теги, клиентский запрос списка); нужен собственный App ID. Не проверено: тестовый App ID 480, порты, достижимость снаружи
- [ ] Очередь на свободное место (как в Squad): сервер заполнен — игрок ждёт и заходит сам, когда место освободилось. Подтверждено 20 октября: игрока в очереди сервер подключает сам; детали (где живёт, что значит «заполнен», сколько держится место) — по умолчанию из раздела 20.7
- [ ] Вход сервера в Steam (модуль `server/steam`) и проверка билета игрока (`BeginAuthSession`) в рукопожатии (разделы 6.3, 20.2, 16.3)
- [ ] Жизненный цикл сервера: набор игроков → бой → следующий бой подряд; опустел — снова набор игроков; состояние боя полностью сбрасывается между боями (раздел 6.3, `server/match_`)
- [ ] Серверная программа для владельцев из сообщества: отдельное приложение-инструмент в Steam + SteamCMD — когда появятся внешние серверы (раздел 6.3)
- [ ] Панель управления сервером, часть 1 — управляющий интерфейс самого сервера (модуль `server/control`): структурированная статистика (числа, не строки лога), админ-команды, чтение и применение файла настроек, мягкая остановка (предупредить игроков, завершить бой, выйти), уровни журнала. Сегодня (коммит `4946f15`, 19 октября) в `main.rs` Ctrl+C уже обрабатывается (`stop_gracefully`), а команды остановки снаружи, предупреждения игроков, файла настроек и самого управляющего интерфейса нет — это писать (раздел 6.4)
- [ ] Панель управления сервером, часть 2 — надзиратель на Go (`ops/orchestrator`): старт/стоп/убить процесс, чтение вывода как консоли, память и процессор процесса, размеры папок, проверка доступности порта снаружи, профили серверов; два режима — одна машина владельца и парк разработчика (разделы 6.2, 6.4)
- [ ] Панель управления сервером, часть 3 — «лицо»: окно программы на собственном UI движка (решено 20 октября; `crates/panel`); делается после готовности UI (фаза 8), до этого — текстовая консоль команд. Экран по образцу MCoffline: состояние, игроки N/200 и по сторонам N/100, профиль, журнал с фильтром, память и процессор, время тика против 33 мс, сеть, бой, адрес и порт, консоль команд, макросы (раздел 6.4)

## Открытые решения, блокирующие соответствующие фазы

- Захват в лок и переключатель (фаза 7) — оспаривается, объяснение ещё не дано
- Личный бой игрок-против-игрока (фаза 5, абордаж) — не спроектирован вообще
- Точная механика шагов ремонта (фаза 7)
- Шейдеры: один исходник или нет (фаза 8)
- Защищённая зона — решено: вход разрешён, орудия не стреляют, нарушитель уничтожается через 5 секунд; чинит плавучая база внутри (радиус 100 м). Открыт только вопрос названия/подачи уничтожающего эффекта (фаза 7, раздел 18.1)
- Управление тягой — решено, непрерывный газ
- Физика столкновения при таране — решено: отскок по сохранению импульса; сцепка — отдельный добровольный механизм абордажа (раздел 19.6)
- Взрыв топливных отсеков — решено: локальный, не катастрофа на весь корабль (раздел 9.3)
- Голосовой канал при абордаже — решено само собой (локальный канал по расстоянию, не по кораблю)
- Мировая вертикаль или палуба при крене — ждёт практики, не блокирует старт (фаза 5)
- Абордаж на свои корабли и высадка малых судов на эсминцы — геймдизайн подтверждён, конкретные числа (дистанция стыковки, скорость) не заданы (фаза 5)
- Автоподбор игроков в бой («матчмейкинг») — решено: нет, игрок выбирает сервер из списка, как в Squad (раздел 6.1)
- Время жизни процесса сервера — решено: много боёв подряд, пока не опустеет, потом режим набора игроков. Открыто: минимум игроков для старта боя и что происходит между боями (фаза 6, раздел 6.3)
- Список серверов — решено: через Steam; серверы держат и разработчик, и сообщество. Остаётся проверить на практике: тестовый App ID 480, порты, достижимость; принимать ли репутацию с серверов сообщества (по умолчанию — только с серверов разработчика) (фаза 6, раздел 6.3)
- Смена стороны по клавише (по умолчанию CAPS LOCK) и резерв места на 1 минуту после вылета — решено; пост освобождается сразу (подтверждено 20 октября) (раздел 20.7)
- Очередь на свободное место — решено: игрока подключает сервер сам; детали по умолчанию (на игровом сервере, длина ограничена, место держится 1 минуту) — поправить, если иначе (фаза 6, раздел 20.7)
- Страна и фракция при входе: что это такое и как связано со стороной — спрошено у пользователя; пауза при смене стороны — обязательна, длительность по тестам; допуск разницы при блокировке по балансу (фаза 6, раздел 20.7)
- Куда возвращается игрок после вылета — отложено: пользователь скажет на этапе создания 3D-моделей; по умолчанию — точка появления своей стороны (раздел 20.7)
- Панель управления сервером — решено: по образцу MCoffline, те же значения и функции, переложенные на игру (раздел 6.4)
- Панель управления — решено: окно программы на собственном UI движка (раздел 6.4). Открыто: когда нужно удалённое управление (по умолчанию позже); за сколько предупреждать игроков при мягкой остановке и что делать с идущим боем; где живут профили серверов; надзиратель отдельной программой на Go или частью окна (фаза 6, раздел 6.4)
