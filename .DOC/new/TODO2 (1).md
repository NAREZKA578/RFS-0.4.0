- [ ] Слои репликации и интерес (раздел 3) — числа частот НЕ трогать до результатов стресс-теста

Решает сервер в момент запроса, не меню клиента; нужно отдельное состояние игрока «подключён, сторону не выбрал» (раздел 20.7). В первом сквозном пути (фаза 1) этого шага нет
- [ ] Конфиг сервера — файл настроек владельца, пока: блокировка выбора стороны и потолок команды (раздел 23, `server/config`); редактируется из панели управления (раздел 6.4)
- [ ] Список серверов — через Steam (решено как направление, раздел 6.3): автоподбора игроков в бой нет, игрок выбирает сервер из списка. Серверная сторона Steamworks проверена по документации (вход сервера в Steam, название/карта/игроки/теги, клиентский запрос списка); нужен собственный App ID. Не проверено: тестовый App ID 480, порты, достижимость снаружи
- [ ] Очередь на свободное место (как в Squad): сервер заполнен — игрок ждёт и заходит сам, когда место освободилось. Подтверждено 20 октября: игрока в очереди сервер подключает сам; детали (где живёт, что значит «заполнен», сколько держится место) — по умолчанию из раздела 20.7
- [ ] Вход сервера в Steam (модуль `server/steam`) и проверка билета игрока (`BeginAuthSession`) в рукопожатии (разделы 6.3, 20.2, 16.3)
- [ ] Жизненный цикл сервера: набор игроков → бой → следующий бой подряд; опустел — снова набор игроков; состояние боя полностью сбрасывается между боями (раздел 6.3, `server/match_`)
- [ ] Конец боя и ожидание возрождения (разделы 10.7 и 20.8, решено 27 октября): бой кончается, когда у одной стороны тикеты на нуле, побеждает другая (как в Squad; числа по тестам); после гибели корабля игрок ждёт в меню, которое открывается на CAPS LOCK; затем — моё прочтение — возрождение в защищённой зоне на заменяющем корабле. Заготовка есть: временная команда возрождения агентов (№701) — сразу на первый живой корабль, без меню, паузы и зоны
- [ ] Серверная программа для владельцев из сообщества: отдельное приложение-инструмент в Steam + SteamCMD — когда появятся внешние серверы (раздел 6.3)
- [ ] Панель управления сервером, часть 1 — управляющий интерфейс самого сервера (модуль `server/control`): структурированная статистика (числа, не строки лога), админ-команды, чтение и применение файла настроек, мягкая остановка (решено 27 октября: игрокам предупреждение за 60, 30 и 10 секунд, идущий бой завершается без результата, при пустом сервере — сразу), уровни журнала. Сегодня (коммит `20dbf8c`, 27 октября; проверено 28 октября): сервер разрезан на библиотеку, есть файл настроек (`server_config.json`, пока `vote_kick` и `auth_token`), Ctrl+C обрабатывается (`stop_gracefully`), память сервера теперь измеряется (`ws_mb` в строке `perf:`); самого управляющего интерфейса, остановки командой, предупреждения игроков и живого журнала нет. Оба решения, которых ждали агенты, приняты 27 октября: закрытый порт на этом компьютере, запрос и ответ — одна строка JSON; отдельный токен управления (не `auth_token` игроков — он теперь ключ подписи пакетов, №700), ограничение частоты запросов, журнал действий. Полный план в 7 этапов — `server-interface-plan.md`; этапы 1–2 («читать» и «управлять» через консольную утилиту `ctl`, которая делается раньше окна) можно начинать сразу, без UI и Steam (раздел 6.4)
- [ ] Панель управления сервером, часть 2 — надзиратель на Go (`ops/orchestrator`): старт/стоп/убить процесс, чтение вывода как консоли, память и процессор процесса, размеры папок, проверка доступности порта снаружи, профили серверов; два режима — одна машина владельца и парк разработчика; решено 27 октября: отдельная программа на Go, окно её запускает (разделы 6.2, 6.4)
- [ ] Панель управления сервером, часть 3 — «лицо»: окно программы на собственном UI движка (решено 20 октября; `crates/panel`); делается после готовности UI (фаза 8), до этого — консольная утилита `ctl` (решено 27 октября). Условие для окна: шрифт UI с русскими буквами — сегодняшний встроенный шрифт покрывает только латиницу, цифры и знаки (`server-interface-plan.md`, раздел 7.3). Экран по образцу MCoffline: состояние, игроки N/200 и по сторонам N/100, профиль, журнал с фильтром, память и процессор, время тика против 33 мс, сеть, бой, адрес и порт, консоль команд, макросы (раздел 6.4)
