## 1. Жёсткий аудит исходного кода

Разговор начался с просьбы о максимально жёстком анализе репозитория на GitHub (RFS-0.4.0, самописный движок). Склонировал репозиторий, собрал через реальный тулчейн (не просто прочитал глазами).

Нашёл: `rfs-core` не компилировался из коробки (несовпадение типов `usize`/`u64` в вызове `bincode::with_limit` в `server_discovery.rs`) — воспроизвёл на их же `Cargo.lock`, на двух версиях rustc. Флагманский пример из README (`engine_demo`) тоже не собирался — неверные пути импорта. `cargo test` падал — баг в самом тесте: юникод-эскейп `\u{202Eb}` в Rust жадно схватывал 5 hex-символов как один кодпоинт вместо задуманного RTL-override плюс буквы "b" — то есть защита от bidi-спуфинга в чате никогда реально не тестировалась. Нашёл мёртвый код (enum-значения DirectX11/12 без объявленных фич — недостижимый код, выдающий себя за рабочую опцию), `slide_move_optimized` не дающий заявленной оптимизации (пересобирал spatial grid на каждый вызов вместо одного раза на всех), гонку в `atomic_write` (детерминированное имя tmp-файла), CRC32 без аутентификации.

Отметил и хорошее: `ChunkAssembler` с грамотной защитой от DoS, `SessionStore` с единой точкой выхода, чистый clippy.

## 8. Сеть — глубокий разбор

Модель авторитетности, ярусы репликации (корабль/отсеки/игрок/снаряды), interest management. Проверил реальные цифры: Squad упирается в 100 игроков, Reforger — в 128, оба объясняют это полной репликацией всего всем — у морского боя структурное преимущество (немного крупных кораблей-контейнеров вместо сотен свободных пехотинцев). Баллистика — медленные снаряды как преимущество перед лаг-компенсацией шутеров.

## 9. Сервер как процесс

Один процесс = один матч, двухфазный тик (параллельная фаза по кораблям через rayon → общая фаза для столкновений), сеть отдельным потоком от тика. Оркестрация — проверил Agones (перешёл под CNCF в марте 2026), рекомендация — свой минимальный оркестратор сначала, Agones при реальном масштабе. Хостинг — выделенные ядра, не шумное общее облако.

## 10. Корабль как мини-мир

Локальная система координат (мировая позиция корабля f64, всё внутри — в локальном пространстве). Посты как отдельные сущности. Классы кораблей — данные (glTF с именованными точками), не код.

## 11. Физика воды

Формула Торричелли для скорости истечения через пробоину (квадратный корень от 2×g×h), резервная плавучесть по принципу Архимеда как физический смысл "сколько воды выдержит корабль".

## 12. Погода

## 13. Гибель корабля

Три пути: затопление выше резерва (таймер-гонка, не статичное ожидание — вода продолжает прибывать), опрокидывание (порог угла, точка невозврата), взрыв погреба (пробитие бронёй как триггер). Эвакуация и тикеты.
